# Basgiath v1.1 — data safety and reading fixes

V1.1 is a maintenance release on the existing database schema. It does not introduce the v2 catalog model or migrate production rows.

## Changes

- JSON restore preserves nested book metadata, including ratings, tags, and provider identifiers. Older archives without metadata remain supported.
- Unsupported archive versions, duplicate source IDs, and broken margin references are rejected before replacement begins.
- Imports remain replacement operations, with a count preview and explicit confirmation. They do not merge libraries. A failure during database restoration rolls back the transaction.
- Missing settings rows are created during settings updates/restores.
- Private updates/deletes require record ownership; adding a margin checks ownership of its book.
- Export reads an authenticated, repeatable-read database snapshot and adds the current browser's appearance preferences. Failed exports do not download a partial client-state backup.
- Reading completion is awaited and serialized against the saved book; repeated completion while already finished does not create a duplicate read. A reread first returns the book to reading.
- Audiobook fields correctly say minutes, and reread resets audio progress. Historical numeric data is not automatically converted.
- Past Reads uses the same completion-based collection in list and bookshelf modes, including books currently being reread or marked DNF.
- Failed loads and reading saves show feedback. Failed progress/finish saves preserve the user's input.
- No rating displays as “Not rated.”

## Verification

Run on Node 22.12+ with the lockfile dependencies:

```sh
npm ci
npm test
npm run typecheck
npm run build
npm run lint
```

The database regression tests use an isolated in-memory PostgreSQL runtime (PGlite). They do not read `DATABASE_URL` or connect to Railway. They cover metadata round trips, owner isolation, import failure rollback, missing settings, duplicate completion, and export scope. A deployed PostgreSQL smoke test and full backup restore drill remain separate operational checks.

Repository-wide lint has pre-existing formatting/type-style debt; consult the implementation report for the final outcome. Do not silently disable checks to make the release look green.

## Release checklist

- [ ] Review the v1.1 diff and successful test/typecheck/build results.
- [ ] Record the current Railway application deployment/commit and schema ledger.
- [ ] Verify a recent PostgreSQL backup; restore a copy into isolated staging before any later v2 migration.
- [ ] Keep an existing JSON export and capture browser preferences. After deploying v1.1, make a fresh export using the repaired path.
- [ ] Deploy the application only. **Do not run `db:push` or new database migrations for v1.1.** The metadata typing change has no SQL effect.
- [ ] Confirm `/healthz` and `/readyz` on the deployed app.
- [ ] Use a disposable test account to smoke-test sign-in, progress, finish/reread, margin creation, and export. Exercise replacement import only on that test account.
- [ ] Confirm the existing user's library, margins, and history render without editing or replacing them.

## Rollback

Keep the previous application artifact/revision available. No schema reversal is needed. A code rollback does not undo legitimate reading changes already saved. Prefer a targeted forward fix over reintroducing the known metadata/authorization bugs. Never restore an older database over current production merely to roll back application code; doing so could erase new reading activity.

## Limits and deferred v2 work

This patch does not repair metadata already lost by older imports when no original export/backup retains it. It does not infer missing read starts or daily activity, reinterpret historical audio values, build custom shelves, add canonical works, or perform a production backup/restore by itself. Legacy completion arrays remain; the row-lock completion fix is not a general offline mutation ledger or a substitute for v2 reading sessions. Keep all original backups.
